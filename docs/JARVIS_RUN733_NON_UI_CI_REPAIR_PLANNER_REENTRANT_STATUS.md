## Additional CI forensic correction — CPython inherited `__new__` slot

After [#42584213476](https://github.com/Iam-2squared/ark-ai/actions/runs/42584213476) reached Ubuntu pytest, its Python 3.12 job reported **11,637 passed / 1 failed / 1 skipped** (remaining failure: honest `DisconnectedReadPreflight(...)` raised `TypeError: object.__new__() takes exactly one argument`). The first test repair above corrected the old pregetter expectation, but **the original inherited `__new__` monkeypatch cleanup was insufficient**: a minimal CPython slotted-dataclass experiment demonstrated that assigning `__new__` on a class, restoring `object.__new__`, and even deleting the own-class attribute can leave the C-level `tp_new` slot in an incompatible state.

The [follow-up fixture repair](https://github.com/Iam-2squared/ark-ai/commit/10522667a2dc8f4868e26c0a1fd6883ba7419d64) **never mutates the shared result class `__new__`**. For that case it replaces the module's public result-class alias with a forged class whose constructor raises if run; the original authority check rejects the alias by identity, with zero hostile constructor calls. All fixture variations also assert the original result dataclass remains constructible after cleanup. This changes **only the test fixture** and keeps the production denial exact. No all-platform PASS is inferred prior to the new exact-head CI.
