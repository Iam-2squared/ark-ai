## A. Memory v1 SQLite hydration and corrupt JSON — source + 6 authored tests

- Source commit [7427fa85](https://github.com/Iam-2squared/ark-ai/commit/7427fa8576e9a55e05b94f4c2490d416f392a82a) adds a SQL-side BLOB-byte preflight inside the same pinned `BEGIN` snapshot as `get` / `search`, before either `SELECT *` populates a Python `sqlite3.Row`. It bounds per-row content, metadata, source and search-wide selected hydration bytes. Valid multi-byte UTF-8 content is kept possible by using conservative byte bounds; canonical record decoding still enforces the stricter existing v1 write contract. Metadata JSON parser recursion/overflow is reclassified to `MemorySchemaError` rather than escaping as an uncontrolled raw parser exception. No schema migration or on-disk mutation.
- [New 6-case test](https://github.com/Iam-2squared/ark-ai/commit/4645cb838ba9cb47742b466b792ec64ea2d99628) checks that three over-budget SQLite TEXT fields refuse before `_record`, scoped total byte cap and no DB mutation, deeply nested malformed JSON and valid Japanese/emoji round-trip.
- Initial CI on source-only head `7427fa85` detected six **existing** namespace row-budget tests asserting the established error phrase `namespace scan budget`. New early preflight returned a different refusal phrase. Log evidence: [#43742516458](https://github.com/Iam-2squared/ark-ai/actions/runs/43742516458) Ubuntu 3.12/3.13 each reported 6 failures from `tests/test_memory_search_scan_budget_run419.py` with 16093 tests passing. The behavior still refused oversized namespaces, but the regression against existing diagnostic was real. [Fix `2b51687b`](https://github.com/Iam-2squared/ark-ai/commit/2b51687b6a591807874490b12dc5270fc6d710fb) preserves `namespace scan budget` when row count exceeds the old cap and uses `namespace hydration budget` solely for the independent aggregate byte cap. No limit loosened, no test assertion changed.
- Caveats: This is an SQLite result materialization boundary, **not** independent file custody, authenticated writer identity, persistent provenance, guaranteed whole-process memory use, or protection against corrupt low-level SQLite pages. The preflight and subsequent hydration are snapshot-coherent on the same connection.
