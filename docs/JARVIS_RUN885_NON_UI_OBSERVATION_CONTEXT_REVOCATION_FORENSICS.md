## 1. Observation NUL identity — CI-detected frozen contract conflict and recovery

The initial attempt at source commit `e223ac241974b106477afbcf33f7df20d1accff7` **incorrectly tried to ban NUL labels in the direct frozen ObservationEnvelope**. Existing `tests/test_observation_direct_nul_boundary_run806.py`, `tests/test_observation_direct_nul_identity_run768.py`, and `tests/test_observation_fixture_nul_framing_run745.py` are controlling regression evidence that the direct v1 envelope **deliberately accepts NUL** and distinguishes its JSON-escaped identity from non-NUL labels. By contrast the optional in-memory disconnected fixture adapter already refuses NUL before hashing private bytes. The two contracts must not be conflated.

[CI #43664811983](https://github.com/Iam-2squared/ark-ai/actions/runs/43664811983), Ubuntu Python 3.12, exposed **21 existing test failures** after the initial edit. The source was immediately restored through the normal Contents API at commit `bd5e0c4689a5a16d6fe58cc07512901e8c12cf14`; its restored exact blob SHA is **`10c3b6e1d9f4635394e44dfa8893d3a5b9fccb30`**, equal to pre-Run885. The new seven-case test was corrected, not weakened: direct NUL labels must retain distinct escaped hashes; the stricter fixture must reject NUL source/privacy metadata **before any private payload SHA-256**. Test correction commit: `e1c14c5864ad00c8ce5aa9a2c95b18f3ea22c72e`. No change to frozen ObservationEnvelope v1 remains in the final Run885 source tree. Latest corrected exact-head CI remains unverified at this report correction.

## 2. Personal Context reflected metadata ingress

`MemoryRecord.__post_init__` normally creates a `MappingProxyType` of metadata, yet a frozen slotted record can still be reflectively changed via `object.__setattr__`. The optional Personal Context reviewer previously processed `tuple(sorted(record.metadata.items()))` without verifying this exact mapping/budget first. Now the reviewer refuses replaced non-mappingproxy carriers, more than 64 entries, non-exact key/value strings, and keys/values longer than the existing MemoryWrite 4096-character limit **before private row content hashing or metadata sorting** (`src/ark/personal_context_review.py`, commit `c1092cd7e8fde176facf2ad12d14ba44884c901c`). Ten synthetic cases are in `tests/test_personal_context_metadata_ingress_run885.py` (commit `188abe8e233102ce6215c7dea03cbcd0ad05b30a`), including a malicious `items()` carrier and an accepted exact-boundary mapping. This is an opt-in projection-side admission hardening, NOT a frozen Memory v1 schema/write rule change. A context bundle still cannot grant dispatch or action permission.
